# 状态、冲突与恢复

## 何时读取

创建、恢复、交接、关闭任务状态，处理多个活动任务、上下文压缩或目标冲突时读取。普通连续执行和临时旁支不必加载。

## 先确定任务，再恢复状态

当前任务由人的请求和对话中最近共同确认且未闭合的下一步确定；活动状态只帮助恢复已经确定的任务。提及具体任务、读取它的资料或把它作为试点，不自动改变当前任务。

临时旁支依靠对话返回点；旁支一旦形成独立目标、持久产物和连续下一步，就应在自然检查点晋升为有自身状态的任务。多个任务可以同时 `active`，其状态分别保存各自的位置，不负责表示整个仓库或所有对话的唯一焦点。

恢复或切换时，AI 用一行向人提供当前目标与下一步，状态和完整文档则向 AI 提供可追溯上下文。只有对话与状态仍支持多个会改变行动的解释时，才请求最小澄清。

## 最小恢复顺序

1. 读取与当前请求匹配的活动任务状态，优先使用 `.agents/tasks/*/state.json`；
2. 读取胶囊链接的当前任务或实施文档相关章节；
3. 对照可验证的代码、配置或外部事实；
4. 用 `目标 → 当前阶段 → 唯一下一步` 暴露恢复结果；
5. 仅对可能改变方向的不一致请求人裁决。

## 权威层次

安全、合规和权限边界优先；其后依次考虑可验证事实、人的最新明确确认、已批准的稳定文档、标明来源的暂定假设、AI 推断。时间最新不自动胜出，最初定义也不永久冻结。

## 冲突处理

1. 判断是真冲突，还是抽象层次、适用范围或措辞不同；
2. 列出冲突双方的来源、时间、确认状态和适用范围；
3. 说明各自会改变的行为与风险；
4. 能由事实消解的由 AI 核对，方向性选择才交给人；
5. 记录新共识以及被取代内容，不静默覆盖。

警示必须具体说明可能后果和安全选项，不能只说“存在风险”。处理强度与影响相称，避免把小措辞差异升级成正式评审。

## 任务胶囊边界

任务状态是控制面和索引，复杂任务优先放在 `.agents/tasks/<task-id>/state.json`。它只保存任务标识、生命周期、阶段、当前行动者、唯一下一步、压力或学习模式，以及任务文档、阻塞项和验证债务的引用。目标、不变量、决定、理由、风险分析和学习证据由同一任务目录或所引用的权威文档承载；状态不复制它们的摘要。人的默认审查面按需从状态和权威文档生成，不持久化成第二份事实源。

候选推理、完整历史和插入话题的临时返回点留在对话。状态文件开始出现段落、类型链、多个“人类判断”或与任务文档重复的结论时，视为职责膨胀并迁移正文。长文档先扫描标题，再读取当前阶段对应章节；可以在文档引用中附章节提示，不把章节摘要复制进状态。

上下文压缩或模型切换后，把胶囊视为恢复起点而非绝对真相。恢复信息不足时诚实标记未知，不用流畅补全伪造共识。

## 新任务初始化

新请求没有匹配状态时，先正常理解任务，不以“先建状态”阻塞讨论。任务已经明确需要跨会话推进、持久产物或执行者交接时，在首次持久化或阶段交接前的自然检查点初始化：

1. 从人的自然表达和现有事实提取目标、约束、不变量、成功观察、当前阶段和下一步；只有会改变方向或风险接受的缺口才请求确认。
2. 按当前已有信息选择真实阶段。信息已足够进入实施讨论、代码实施或审查时直接记录该阶段；下面 schema 中的 `task_understanding` 只是示例，不是强制起点。
3. 生成简短稳定的 `task_id`，先检查目标路径。匹配的活动任务应恢复而非重复创建；同名路径属于其他任务时不得覆盖，改用可区分的短标识。
4. 项目任务优先写入 `.agents/tasks/<task-id>/`，并创建最少必要的任务文档和 `state.json`。文档只保存已经稳定、值得恢复的内容，不因初始化预建空的架构、审查或复盘文件。
5. 写入后解析 JSON，并用一行 `目标 → 当前阶段 → 唯一下一步` 向人暴露 AI 的初始化结果；低风险推断可以明示后继续，高风险方向不能把沉默当确认。

若工作区只读、没有合适的项目目录或缺少写入权限，不猜测新的全局位置，也不让状态设施阻塞业务工作。继续在对话中维护最小航标，明确说明“本次状态尚未持久化”及其恢复风险；在用户提供位置、权限恢复或出现合适检查点时再保存。用户已明确指定个人任务根目录时可以使用该位置。

## 最小结构

```json
{
  "schema_version": 1,
  "task_id": "short-stable-id",
  "title": "人可识别的任务名",
  "status": "active",
  "phase": "task_understanding",
  "current_actor": "ai",
  "next_action": "形成目标、不变量与成功观察的最小审查面",
  "pressure_mode": "standard",
  "learning_mode": "off",
  "documents": {
    "task": "task.md"
  },
  "blocker_refs": [],
  "validation_debt_refs": []
}
```

示例字段值用于说明结构，不是初始化默认决策。`current_actor` 是从该检查点恢复后应执行 `next_action` 的一方，不是最后发言者；`next_action` 不再重复写行动者。可选字段没有内容时可省略，但同一任务应保持字段语义稳定。

## 最小生命周期

- `active`：当前任务仍在推进，可以在请求明确匹配时参与恢复；
- `completed`：目标已经完成，不再自动加载；
- `superseded`：已被新的任务定义或胶囊取代，不再自动加载，并记录替代来源。

复杂任务将跨会话推进、已经需要持久任务文档，或明确需要交接时，在自然检查点创建 `.agents/tasks/<task-id>/state.json`；不为简单任务和短暂灵感创建。目标实际完成且约定的审查/复盘已完成或明确跳过后标记 `completed`；任务定义被替代时标记 `superseded` 并记录替代引用。重新启用已结束胶囊时，先确认它仍适用，不直接改回 `active`。

只在阶段或生命周期变化、真正等待另一方、会话/执行者交接、有意义子任务完成后下一步改变，或新增必须跨会话保留的阻塞和引用时更新。连续 AI 执行的中间步骤、普通问答和事实方向未变的恢复不写状态。写入后做 JSON 解析检查；只有反复出现格式或迁移错误时才增加脚本。
