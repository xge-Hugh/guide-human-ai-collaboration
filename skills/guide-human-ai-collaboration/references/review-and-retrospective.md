# 审查、证据与复盘

## 何时读取

进入独立审查、设计验证方案、选择测试层级、要求人审代码、处理生产逃逸缺陷或进入复盘时读取。普通实施自检和简单任务的交付摘要不必加载全文。

## 独立审查边界

- 实施者的静态检查属于自检。独立审查要求 Reviewer 的判断过程或关键证据来源与实施过程形成隔离。
- 进入前说明可用方式，例如人类脚手架审查、新鲜 AI/Agent、外部审查者或不同证据链。AI 先依据风险、成本和可用条件推荐一个默认方式，并明确它为什么适合当前任务（至少落到独立性、人的参与或成本之一）；只列出会实质改变这些因素的替代路径。不要只报模式名称后让人从空白选择。方式会影响成本、工具或人的参与时，让人裁决；已获端到端授权且方式不改变风险时可直接推进。
- Reviewer 从原始目的、不变量和最终差异开始，先形成自己的风险预期，再阅读 Builder 的解释。解释可以澄清，不能充当正确性证据。
- 审查不只找 bug，也检查设计、功能、复杂度、兼容性、可维护性及知识传递；性能、并发、安全、可观测性等按变更路径和业务后果选择，不机械遍历清单。

## 给人的审查脚手架

不要让人直接审几百行差异，也不要只说“凭直觉看看”。按职责或风险把变更分成小切片，每次提供完成当前判断所需的最小交接包：

1. 这一片要保护的目的或不变量；
2. 入口到副作用的变化路径；
3. 一个可理解的代表性例子或代码切片；
4. AI 已识别的主要权衡、风险和证据缺口；
5. 当前希望人判断的具体问题，以及回答可以多短。

人可以讲故事、举反例或跨层表达。AI 负责映射回风险和代码，不把发现所有问题的责任悄悄转移给人。

## 风险—证据匹配

先写清：`变化 → 可能的失效模式 → 业务后果 → 当前证据缺口`。再选择成本最低、但足以区分该风险的证据。判断证据是否合适时看：

- 相关性：是否直接针对该失效模式；
- 保真度：是否覆盖真实边界、运行时、配置、数据或外部系统；
- 判别力：缺陷存在时它是否会失败，判断标准是否可靠；
- 独立性：是否只是复述实现者的同一假设；
- 成本与可重复性：是否有更便宜且同样有效的证据。

常见匹配关系：

| 风险 | 优先证据 |
| --- | --- |
| 纯逻辑、分支、边界值 | 少量针对性单元测试或可执行例子 |
| API 签名、引用和类型依赖 | 目标工具链的编译证据 |
| 路由、绑定、序列化、依赖注入、中间件 | 从真实请求入口执行的聚焦集成或功能验证 |
| 数据库、事务、外部服务和配置契约 | 代表性环境中的集成、重放、smoke 或人工验证 |
| 历史真实请求逃逸 | 先重放原请求，再决定是否值得固化自动回归 |
| N+1 或性能怀疑 | 代表性数据、调用/查询次数、延迟或资源观测，并与业务阈值比较 |
| 用户可见流程 | 演示、验收场景或端到端旅程 |

测试通过只消除它实际覆盖的风险。不要用测试数量、覆盖率或“全绿”代替证据解释；不要为了形式给每个缺陷补单测。只有测试能区分有意义的失效模式、保护高价值回归且维护成本合理时才编写。性能问题没有代表性测量或业务后果时，只记录假设，不要求顺手优化。

始终服从项目权限与执行规则。未获授权或环境不适合运行编译/测试时，分开报告“实现状态”和“验证状态”，并给出简短人工验证契约：要排除的风险、环境前提、精确操作、固定输入、预期可观察结果和需回传证据。没有运行证据时明确保留风险。

## 审查产物路由

- 没有重要发现时，对话中的风险—证据结论通常足够。
- 发现、接受的残余风险或验证证据需要交接时，写入 `review.md` 或 `evidence.md`，不要追加到 `architecture.md`。
- `architecture.md` 只保存当前架构模型、决定、理由和适用边界；修订原决定时更新正文并保留必要取代关系，不写逐轮进展日记。

## 交互式复盘

复盘的目标是从一次真实经历改善下一次表现，不是生成漂亮总结。默认先做一次短复盘；只有出现高价值分歧、重复失效或明确学习目标时才展开。

1. AI 先用客观证据简述“原本想达到什么、实际发生了什么”，只说当前复盘所需内容。
2. 已有人类反馈时先提取，不重新发问卷；需要补充时使用一个开放而有抓力的问题。可采用“我观察到 X，因此担心 Y；你当时怎么看”的表达，公开 AI 的判断并邀请人的视角。
3. 允许人用感受、故事、例子和零散联想回答。AI 再共同分析差异为何发生，不能把责任归结为某个人“应该更小心”。
4. 按需观察四个平面，不要求逐项作答：
   - 任务：结果、证据、逃逸缺陷和剩余风险；
   - 人与 AI：各自贡献、失误、参与感和可迁移学习；
   - 工作流：哪些机制有效、失效或过重；
   - 制约与杠杆：工具、环境、知识、权限或重复摩擦中，什么改进能显著提效。
5. 共同选择极少数下一次可观察的改进。动作要有明确适用场景、责任方和完成信号；没有行动价值的过程材料不持久化。

复盘内容按用途分流：任务教训进入任务/证据文档，协作机制进入工作流或 Skill 候选，能力证据进入任务学习快照，跨任务稳定后才晋升个人画像，制约与杠杆进入独立改进任务。复杂任务可创建 `retrospective.md`；简单任务不因复盘强制增文件。

AI 不能把单方面总结、写入文档或切换 `phase` 当作复盘已经发生。约定包含复盘时，只有人已参与、明确选择跳过，或双方确认无需继续后，才能完成任务状态。结束时直接向人说明共同得到的结论、已落地改进和剩余事项，不要求人另行通读文档。
