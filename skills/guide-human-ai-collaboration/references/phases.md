# 阶段与快速通道

## 何时读取

选择、恢复、进入或退出工作阶段时读取。只做阶段内连续执行且方向未变时不必重复加载。

## 路由原则

阶段用于控制当前抽象层次，不是瀑布门禁。信息已经足够、安全且可逆时继续推进；范围、目标或不变量变化时回到任务理解，方案因果关系变化时回到实施讨论。

| 阶段 | 主要问题 | 最小产物 | 退出信号 |
| --- | --- | --- | --- |
| 任务理解 | 为什么做、什么不能坏 | 目的、范围、关键不变量、成功观察 | 双方能用自己的话说明要解决什么和如何判断 |
| 实施讨论 | 怎样做得正确、简单、适度 | 心智模型、边界、关键取舍、承重可调点、风险与验证 | 人能判断方案方向；可调点已露面或人明示不再谈细；未用整包点头关闸（或已点名快速通道） |
| 代码实施 | 如何把方案变为真实系统 | 最小代码改动、实施偏差、必要证据 | 约定范围完成，未验证项被诚实记录 |
| 独立审查 | 是否做对且没有同源盲点 | 风险、匹配证据、发现、影响和处置 | 关键发现已解决、接受或明确留债 |
| 复盘 | 任务和协作带来了什么 | 共同反思、模型修正、有效改进与路由 | 人已参与或明确跳过，有价值内容被路由 |

## 阶段关注点分流

各阶段有不同主战场，避免后一阶段重开前一阶段已确认共识，或把本单可改问题推到不能改代码的复盘。深度按风险调节。

| 关切 | 主阶段 | 注意 |
| --- | --- | --- |
| 目的、范围、业务不变量 | 任务理解 | |
| 落点/分层、实施语义、命名与复用、关键架构取舍 | 实施讨论 | 可下潜到架构与实施层；允许短骨架与可纠正默认；禁止整包点头+「点头后开写」关死下潜；细讨论按需 |
| 兑现方案、记录偏差与未验证项 | 代码实施 | 方案无法兑现或不变量破坏时才回到讨论 |
| 业务正确性、不变量兑现、失效与证据 | 独立审查 | 已钉死的优雅/DRY/美感不默认重开，除非新风险证据 |
| 薄弱点、教训、债务的下次路由 | 复盘 | 不改本单已接受实现来补审美 |

审查冒出未讨论的架构/优雅问题时，显式选择：打回实施讨论 / 本单接受并留债 / 复盘记下次。

## 实施讨论：深度与退出

- 保留短骨架以降负荷；区分可纠正工作假设 vs 整包待批准草案。
- 充分 ≠ 对整包说了 yes；须方向可判断、承重可调点已露面或人明示不再谈细、下潜入口未关死或已点名快速通道。
- 成长力气用在高杠杆判断；低收益繁琐可交 AI。下一层勿再端成新的整包点头。

完整表述见规范正文 `docs/norm/02-five-phases.md` §5.2 与 §5.6。

## 阶段中的能力机会

阶段既控制交付抽象层次，也暴露不同的可迁移能力，但不要求每个阶段都安排练习：

| 阶段 | 可能观察或练习的能力 |
| --- | --- |
| 任务理解 | 问题定义、范围控制、业务不变量、成功标准、不确定性表达 |
| 实施讨论 | 领域建模、架构边界、因果关系、抽象取舍、方案比较 |
| 代码实施 | 语法与 API、代码组织、调试、协议及底层实现 |
| 独立审查 | 发现假设、识别风险、检查证据、评价权衡、设计验证 |
| 复盘 | 模型修正、跨场景迁移、自我效能校准、后续练习选择 |

代码实施完成后先结算实际变更、实施偏差、已有证据和验证债务。实施者随即进行的静态检查属于实施自检；独立审查和复盘的具体契约见 [审查、证据与复盘](review-and-retrospective.md)。不得因为实现阶段没有阻塞，就静默替人决定审查者、长期执行审查并单方面关单。

## 成熟模式检查点

各阶段遇到承重、陌生或高风险问题时，按需寻找成熟先例，不要求每阶段都联网或产出研究文档：

| 阶段 | 优先参考 |
| --- | --- |
| 任务理解 | 领域定义、法规/官方语义、既有验收与真实事故 |
| 实施讨论 | 仓库先例、官方架构、成熟同类实现和原始研究 |
| 代码实施 | 现有代码惯例、官方 API 与最小可运行示例 |
| 独立审查 | 成熟审查准则、历史逃逸缺陷和风险导向验证 |
| 复盘 | AAR、debrief、blameless postmortem 等成熟反思模式 |

每次只回答三件事：直接借鉴什么、因当前约束适配什么、为什么其余内容不采用或必须自研。先例提供比较框架，不替代业务不变量和当前证据；检索边际收益降低时停止。

## 快速通道

- 简单、低风险、机械任务：在对话中确认目标后直接实施并简短交付。
- 时间紧但风险可控：AI 明示假设后先做可逆步骤，延后解释与学习。
- 紧急且高风险：只压缩形式，不跳过业务不变量、不可逆风险、权限边界和验证债务。
- 不因模板字段未填满阻止推进；不以文件数量证明阶段完成。

## 阶段结算

只输出本阶段新增的承重信息：已确认、发生变化、仍未知、唯一下一步。人的确认只针对会改变方向或风险接受的事项。
