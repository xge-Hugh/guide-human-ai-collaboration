# 项目证据与主张边界

> 地位：**当前项目证据治理方法**。本文件约束本项目自己可以把观察、研究、实验和设计判断说到多强；它不是普通协作任务必须逐项执行的规范。

## 1. 不把不同主张来源混成一种“证据”

项目至少区分：

| 类型 | 含义 |
| --- | --- |
| 观察 / pilot evidence | 在具体任务、用户、模型、载体和环境中实际发生了什么 |
| 研究证据 | 外部研究或成熟实践在其样本与方法边界内支持什么 |
| 设计推断 / hypothesis | 基于观察、理论或工程经验提出的可验证解释/机制 |
| 规范选择 | 项目决定希望保护什么人机关系、权威或认识论边界 |
| 实验性实现 | 为检验价值或运行方式而采用的具体 Skill、模板、状态或工具 |
| 当前未知 | 证据不足，不能合理升级为更强结论的部分 |

规范选择可以参考经验和研究，但不能伪装成“科学已经证明的唯一正确价值”。反过来，经验机制或科学假设也不能仅因写入规范目录就获得事实权威。

## 2. 主张强度不能超过证据

常见错误包括：

- 一个真实任务成功 → “Skill 已被验证可靠”；
- 一个知情用户能持续纠偏 → “新用户也能安全使用”；
- 一个实验中出现能力表现 → “人的能力已跨任务迁移”；
- 一篇相关研究 → “当前具体话术/阈值已经被科学证明”；
- 包结构、eval 定义或文档质量良好 → “运行时关键行为会首次机会可靠发生”。

结论应显式保留适用条件、未观察部分、相关失效来源和替代解释。

## 3. 区分规范、载体、运行、保障与结果

评价项目时至少可以区分：

```text
规范 / 语义模型
    理想条件是否值得保护、是否自洽？

载体 / 实现
    Skill、文档、状态、UI 等是否清楚、可维护？

运行表现
    模型在真实交互中是否实际执行关键行为？

执行保障
    关键状态、证据与不变量能否被观察、检查、恢复？

结果与体验
    任务是否成功；人的判断、补偿劳动、疲劳和学习如何？
```

某一层的通过不能自动证明其他层。

## 4. 成功、恢复和失败分开记录

当评估运行行为时，不只看最终结果。可以至少区分：

- `pass`：关键行为在首次合适机会发生；
- `recovered`：最初未发生，经人/外部机制提醒或纠偏后恢复；
- `fail`：关键行为未发生且造成未恢复的失效；
- `not_observed`：当前任务没有形成足以判断的情境或证据。

这不是要求所有实验都使用固定四级评分，而是防止“最后做对了”抹掉运行保障缺口。

## 5. 人的投入也需要按评价对象解释

人的参与至少可能包含：

- 不可替代的目的、领域语义、价值、风险接受和最终裁决；
- 为弥补 AI 或保障设施缺口而承担的规则召回、状态维护、证据一致性和流程修复劳动。

两类投入都真实，但不能用“人参与充分”把补偿性劳动吸收到成功指标中，从而高估载体或 AI 自主表现。

当前项目不设置固定补偿劳动比例；需要时保留定性证据即可。

## 6. 科学与工程化表述边界

项目会借鉴认知卸载、自动化偏差、认知负荷、脚手架、自我效能、检索练习、类比迁移、多媒体学习、复盘等研究，但保持以下边界：

- AI 可能改变认知分工并带来过度依赖风险，不等于“使用 AI 必然导致永久认知下降”；
- 压力可能影响执行功能，但效果依赖任务、控制感、强度和个体差异；
- 独立预测可以暴露当前模型，一次预测正确不等于掌握；
- 能解释不等于能执行，执行一次不等于能够迁移；
- 自我效能不等于客观能力；
- 选择、填空、局部实现到独立设计可以作为支架，但不是普遍唯一序列；
- 远迁移通常需要单独证据；
- 图文、动画、视频、故事和类比可以帮助理解，但不能自动证明事实或机制；
- 结构化复盘可以有价值，但具体问题模板、评分、徽章或排行榜不是普遍有效结论；
- 80/20、固定时间预算、固定能力级别等工程启发不能包装成科学定律；
- 本项目不是心理测评，不推断智力、人格、心理健康或职业等级；
- 当前规格和指导应继续接受真实任务修订，不宣称对所有人和所有任务最优。

## 7. 外部研究如何进入项目

外部研究进入项目时至少记录：

1. 研究实际回答的问题；
2. 样本、场景、媒介或任务与本项目的差异；
3. 它支持的是背景风险、机制假设、设计启发还是具体行为；
4. 哪些外推仍未经验证；
5. 当前项目因此改变了什么、没有改变什么。

研究汇总应集中维护，避免同一个事实在规范、insight 和 Skill 中被多次转述后逐渐漂移。

## 8. 项目方法也不自证

分类框架、关系词汇、eval 体系和本证据政策本身都只是当前项目方法。若它们在真实维护中产生系统性误分类、过高成本或错误安全感，应记录为项目反馈并修订。

方法通过可检查、可比较和可取代获得可信度，不通过“这是治理层”获得更高事实权威。
