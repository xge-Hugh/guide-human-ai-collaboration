# 决策治理与历史记录

> 地位：**项目治理记录**。本文件说明历史决策如何被解释和维护；它不是人机协作规范正文。当前协作要求以 [`../spec/`](../spec/README.md) 为准。

## 1. 决策记录回答什么

决策记录用于保存：项目在某一时点面对什么问题、采用了什么方向、为什么这样选择，以及后来是否被缩窄、重分类或取代。

因此，“曾经采纳”与“当前仍是规范”不是同一件事。历史决策可以属于不同语义层：规范选择、概念模型、工作流、指导方法、载体/实现、试点安排、治理方法或延期事项。

## 2. 当前权威规则

- 当前规格、指导和治理正文定义项目**现在**如何解释相关内容；
- 决策记录提供来源与演进背景，不与当前正文并列成第二事实源；
- 若历史决策与当前正文冲突，以当前正文及明确的取代/缩窄关系为准；
- `D-###` 编号作为历史引用标识保留，不因重分类而机械改号。

## 3. 后续维护状态

对仍需维护的决策，可按实际情况标记：

- `current`：当前仍有效，且没有被更具体正文取代；
- `narrowed`：核心方向仍有效，但适用范围或强度已缩小；
- `reclassified`：内容仍有价值，但已被确认属于不同语义层；
- `superseded`：已有新的当前决定或正文取代；
- `deferred`：问题仍存在，但当前没有足够依据选型；
- `historical`：仅保留来源、试点或演进背景。

这些是**当前地位**，不同于 Issue 的 open/closed、任务的 active/completed，或某项机制的验证状态。

## 4. 旧记录如何迁移

旧 `docs/norm/decisions.md` 混合了规范、工作流、实现、试点与延期事项。为避免一次性重写历史，本轮先原样保存为 [`decision-log-v0.16.md`](decision-log-v0.16.md)。

后续不要求把全部旧条目立刻重写成新表。只有当某项决策再次被维护、引用或与当前结构发生关系时，才补充其 `current / narrowed / reclassified / superseded / deferred / historical` 地位及对应当前正文链接。

这种按需重分类保留历史事实，同时避免把旧目录位置或旧“已采纳”字段误读为当前规范权威。
