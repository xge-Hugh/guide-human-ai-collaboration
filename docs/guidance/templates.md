# 可裁剪模板

> 地位：**操作载体示例**。模板的价值在于提醒人和 AI 处理当前任务真正需要的内容，不是要求人逐项填表，也不是合规证明。

优先从自然表达中提取已有信息；只有结构化载体能降低未来恢复、比较、交接或高风险确认成本时才显式使用模板。字段按目的裁剪。

## 1. 轻量工作包

```markdown
# 工作包：<标题>

- 状态：
- 当前目的：
- 目标：
- 为什么现在做：
- 范围内：
- 范围外：
- 已知事实：
- 未知项：
- 关键约束与不变量：
- 成功标准：
- 已有人类判断痕迹：
- 首选方向：
- 关键风险 → 证据/验证：
- 学习目标（如有）：
- 审查/保障安排：
- 待人决策：
- 下一步：
```

不要求为了完整而补齐空字段。已有事实、偏好或判断应从现有对话/来源吸收，而不是让人重新录入。

## 2. 学习插槽

```markdown
## 学习插槽：<名称>

- 学习目标：
- 与当前任务的关系：
- 负责对象 / 允许修改范围：
- 必须保持的不变量：
- 当前可观察起点：
- 希望取得的下一层证据：
- AI 当前支援：示范 / 步骤 / 局部提示 / 审查
- 交还条件：
- 迁移或后续练习：
```

学习插槽是短小、可撤回的载体，不应成为交付门禁。固定“选择→填空→代码→函数”等阶梯只是一种可能支架，不必写进每次模板。

## 3. 能力诊断记录

```markdown
## 能力诊断：<概念 / 能力>

- 为什么需要诊断：
- 当前情境与抽象层：
- 观察 / 微型问题：
- 人的判断与理由：
- AI / 工具支援程度：
- 本次观察支持什么：
- 本次观察不能证明什么：
- 是否需要不同情境的第二条证据：
```

诊断应服务支援调节，不形成永久能力标签。允许“不确定”；一次错误只是一条观察。

## 4. 类比卡

```markdown
# 类比卡：<名称>

- 目标概念：
- 熟悉来源：
- 对应关系：
- 可以推出：
- 不能推出：
- 断裂点 / 反例：
- 正式模型：
- 迁移检查：
```

类比卡用于避免把表面相似误当成机制等价；类比不能替代真实证据。

## 5. 结算 / 复盘载体

```markdown
# 结算：<任务>

## 结果与证据
- 完成内容：
- 验证证据：
- 未验证事项：
- 残余风险及负责人：

## 模型修正
- 关键预期 / 假设：
- 实际结果：
- 哪些解释得到支持：
- 哪些解释仍待验证：
- 更新后的模型：

## 能力与协作
- 人的关键贡献与当前证据：
- AI 的关键贡献：
- 仍依赖的支援：

## 路由
- 当前无需行动：
- 研究问题：
- 技术 / 认知 / 流程债务：
- 真正承诺执行的少数动作：
- 尚未结事项：
```

复盘载体只能记录已经发生的共同分析，不能用“表格填完”证明复盘已经完成。明确预约、重要发现与高价值未结问题必须得到有理由的处置或保留，而不是为了模板收口被静默丢弃。

## 6. 什么时候不用模板

以下情况通常不需要生成新模板：

- 简单、低风险、一次性任务；
- 信息已经清楚存在于可检索来源；
- 模板不会改变判断、风险、恢复或交接；
- 显式结构会把 AI 的整理成本转嫁成人；
- 用户当前需要的是完整成果而不是过程表单。
