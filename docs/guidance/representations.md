# 表示与文档指导

> 地位：**可替换指导**。本文件说明如何根据当前信息结构、受众和任务选择表示与文档载体；派生表示的权威边界仍由 [`../spec/norms.md`](../spec/norms.md#34-派生表示不自动继承来源的完整性与权威) 约束。

## 1. 形式服务于要显露的关系

常见路由：

| 信息结构 | 常见合适形式 |
| --- | --- |
| 单一结论与原因 | 短文字 |
| 并列项和检查项 | 列表 |
| 多对象重复字段比较 | 表格 |
| 层级、依赖和组件关系 | 结构图或树 |
| 分支、因果和数据流 | 流程图 |
| 状态变化和异步过程 | 时间线或状态图 |
| 精确执行语义 | 代码 |
| 抽象规则落地 | 代表性例子 |
| 参数变化影响结果 | 交互演示 |
| 连续运动和界面操作 | 动画或短视频 |

这不是固定映射表。选择形式时看：当前判断需要看见什么关系、人的已有知识、风险、载体、后续复查与可搜索需求。

## 2. 一份语义，多个互补视图

文字、表格、图、代码和示例可以互补，但每个新视图应回答前一视图没有回答的问题。增加表示也会增加选择、翻译与整合成本。

转换表示时说明：

- 新视图要显露什么；
- 保留了什么；
- 压缩或省略了什么；
- 重要不确定性和限制在哪里；
- 如何回到权威来源或证据。

新视图不是无损副本，也不是因为更清晰就成为第二事实源。

## 3. 渐进披露不是固定输出顺序

过程性交互可以从简短状态与核心依据逐步下钻到完整边界、日志、代码和证据，但“先摘要再分片”不是所有成果的默认交付方式。

论文、教程、报告、规范、设计说明等本身就是完整交付物时，应按体裁形成可独立阅读的正文。会话摘要和审查面用于导航，不替代完整成果，也不应强迫用户不断输入“继续”才能取得正文。

## 4. 文档按未来问题路由

选择文档载体时先问：以后谁需要回答什么问题？

| 未来问题 | 常见载体 |
| --- | --- |
| 单次任务发生了什么 | 工作包或交付记录 |
| 为什么这样选择 | 决策记录或设计文档 |
| 如何使用稳定能力 | 使用说明或 API 契约 |
| 出问题时如何处置 | Runbook |
| 某段实现为何反常 | 就地注释 |
| 可复用协作模式 | 规格、指导或知识库 |
| 尚未验证的想法 | insight、实验记录或 Issue |

文档量由复用价值、决策成本、风险、寿命和受众决定，不由代码行数或流程阶段数量决定。

## 5. 人的审查面与完整来源分工

完整任务、实施和证据文档可以服务 AI 连续执行、上下文恢复和独立审查，但不默认要求人逐字通读。

人通常应在与责任匹配的抽象层看到：

- 目的与关键不变量；
- 改变方向的取舍；
- 重大风险和未知；
- 待裁决事项；
- 当前下一步与来源入口。

AI 可以生成最小审查面，但该视图不能独立演化或静默覆盖完整文档。高影响内容应能追溯到相应章节、原始证据和适用边界。

## 6. 冲突时保留来源与取代关系

任务文档、后续对话、代码事实和 AI 摘要可能不一致。发现冲突时：

1. 先判断是否只是补充、抽象层不同或术语差异；
2. 只暂停受影响动作；
3. 呈现真正互斥的说法、来源与影响；
4. 能由事实核对解决的先核对；
5. 只有会改变方向且不能由证据解决的冲突才交由有权人裁决；
6. 裁决后更新当前来源，并明确旧内容被取代，而不是静默覆盖。

## 7. 可访问性与可恢复性

图示应有文字说明，颜色不作为唯一编码；视频/动画在重要场景应有静态摘要、字幕/文字稿或关键帧。重要信息应尽可能可搜索、可复制并有静态回退。

写了但未来无法发现、没有来源、没有失效条件或长期无人维护的文档，不自动构成有效知识沉淀。

## 8. 共同航标：固定语义，适配载体

共同航标用于在上下文恢复、任务切换、阶段转换、明显分叉或高影响行动前外化共享位置感，降低工作记忆负担，并让人能及时发现 AI 对议程、所处状态或下一步的误判。它不是进度条、项目管理副本、权限证明，也不是每轮都要显示的固定控件。

最小语义通常只有三件事：

- **目标**：当前共同服务的一个目标；
- **现在**：当前真正所处的阶段、关注点或活动。可以把内部阶段名翻译成人能直接理解的自然语言，不必暴露状态机字段；
- **下一步**：与“现在”同层、可执行且唯一的下一动作。当前阶段尚未闭合时，不把未来阶段写成已经可直接执行的下一步。

呈现方式按载体和扫读需要逐级增强：

1. **自然短句优先**：若一句话已经能无歧义地表达三件事，就不另造控件，例如“我们仍在完善协作 Skill；现在收口航标呈现，接下来先更新表示指导。”
2. **紧凑分行用于扫读**：需要更明显的视觉锚点时，用两到三行短标签，而不是把信息压成公式：

   ```text
   目标：完善协作 Skill
   现在：收口共同航标的呈现规则
   下一步：更新 Skill 与恢复规则
   ```

3. **富 UI 只做渐进增强**：支持卡片、chip、时间线、状态条或其他组件的载体可以用它们增强扫读，但同一语义必须保留可搜索、可复制的纯文本回退。图标可以作为冗余提示，不能单独承担含义；颜色也不能成为唯一编码。

对只有三个短字段、且会频繁变化的航标，图片或生成式图形通常不会比文字增加足够的信息价值，反而增加生成、搜索、复制、无障碍和 CLI 兼容成本。只有当需要显露真实的空间、分支、依赖或多状态关系时，才值得升级为图或时间线。

航标按事件触发而不是按轮次触发。普通连续推进中，如果当前对话已经清楚表达目标、现在和下一步，且没有实质状态变化，可以不单独展示航标，只报告变化；发生恢复、切换、阶段变化、计划中断、明显分叉或高影响动作前，再显式提供可纠正的定位视图。
