# 表示与文档指导

> 地位：**可替换指导**。本文件说明如何根据当前信息结构、受众和任务选择表示与文档载体；派生表示的权威边界仍由 [`../spec/norms.md`](../spec/norms.md#34-派生表示不自动继承来源的完整性与权威) 约束。

## 1. 形式服务于要显露的关系

常见路由：

| 信息结构 | 常见合适形式 |
| --- | --- |
| 单一结论与原因 | 短文字 |
| 并列项和检查项 | 列表 |
| 多对象重复字段比较 | 表格 |
| 层级、依赖和组件关系 | 结构图或树 |
| 分支、因果和数据流 | 流程图 |
| 状态变化和异步过程 | 时间线或状态图 |
| 精确执行语义 | 代码 |
| 抽象规则落地 | 代表性例子 |
| 参数变化影响结果 | 交互演示 |
| 连续运动和界面操作 | 动画或短视频 |

这不是固定映射表。选择形式时看：当前判断需要看见什么关系、人的已有知识、风险、载体、后续复查与可搜索需求。

## 2. 一份语义，多个互补视图

文字、表格、图、代码和示例可以互补，但每个新视图应回答前一视图没有回答的问题。增加表示也会增加选择、翻译与整合成本。

转换表示时说明：

- 新视图要显露什么；
- 保留了什么；
- 压缩或省略了什么；
- 重要不确定性和限制在哪里；
- 如何回到权威来源或证据。

新视图不是无损副本，也不是因为更清晰就成为第二事实源。

## 3. 渐进披露不是固定输出顺序

过程性交互可以从简短状态与核心依据逐步下钻到完整边界、日志、代码和证据，但“先摘要再分片”不是所有成果的默认交付方式。

论文、教程、报告、规范、设计说明等本身就是完整交付物时，应按体裁形成可独立阅读的正文。会话摘要和审查面用于导航，不替代完整成果，也不应强迫用户不断输入“继续”才能取得正文。

## 4. 文档按未来问题路由

选择文档载体时先问：以后谁需要回答什么问题？

| 未来问题 | 常见载体 |
| --- | --- |
| 单次任务发生了什么 | 工作包或交付记录 |
| 为什么这样选择 | 决策记录或设计文档 |
| 如何使用稳定能力 | 使用说明或 API 契约 |
| 出问题时如何处置 | Runbook |
| 某段实现为何反常 | 就地注释 |
| 可复用协作模式 | 规格、指导或知识库 |
| 尚未验证的想法 | insight、实验记录或 Issue |

文档量由复用价值、决策成本、风险、寿命和受众决定，不由代码行数或流程阶段数量决定。

## 5. 人的审查面与完整来源分工

完整任务、实施和证据文档可以服务 AI 连续执行、上下文恢复和独立审查，但不默认要求人逐字通读。

人通常应在与责任匹配的抽象层看到：

- 目的与关键不变量；
- 改变方向的取舍；
- 重大风险和未知；
- 待裁决事项；
- 当前下一步与来源入口。

AI 可以生成最小审查面，但该视图不能独立演化或静默覆盖完整文档。高影响内容应能追溯到相应章节、原始证据和适用边界。

## 6. 冲突时保留来源与取代关系

任务文档、后续对话、代码事实和 AI 摘要可能不一致。发现冲突时：

1. 先判断是否只是补充、抽象层不同或术语差异；
2. 只暂停受影响动作；
3. 呈现真正互斥的说法、来源与影响；
4. 能由事实核对解决的先核对；
5. 只有会改变方向且不能由证据解决的冲突才交由有权人裁决；
6. 裁决后更新当前来源，并明确旧内容被取代，而不是静默覆盖。

## 7. 可访问性与可恢复性

图示应有文字说明，颜色不作为唯一编码；视频/动画在重要场景应有静态摘要、字幕/文字稿或关键帧。重要信息应尽可能可搜索、可复制并有静态回退。

写了但未来无法发现、没有来源、没有失效条件或长期无人维护的文档，不自动构成有效知识沉淀。

## 8. 重建线索视图：固定功能，按需选择

长上下文、恢复、分叉、计划中断和承重模型变化会让人需要重新建立“为什么走到这里、哪些关系仍成立、什么还没闭合”的任务相关模型。此时可以提供一个短小的**重建线索视图**，帮助激活足够的推理路径并降低工作记忆负担。它不是共享状态机、进度条、项目管理副本、权限证明，也不要求人和 AI 的内部模型完全一致。

固定的是功能，不是字段。生成视图前先问：**下一次有意义的判断、行动或审查，需要恢复什么才能继续判断当前模型是否仍适用？** 然后只选择最少的高杠杆线索。可观察的重建风险包括：上下文中断或明显变长、局部分支遮蔽原目的、已有承重模型被新证据修正、已确认计划或返回点仍未闭合、会改变行动的重要分歧、AI 压缩会遮蔽关键因果/来源/异常，以及持久化线索可能已经被新事实取代。

候选线索来自真实任务关系，而不是固定 schema，例如：

- 原始目的或当前仍承重的不变量；
- 一个已经成立且能解释后续方向的 checkpoint / 结果；
- 尚未闭合的承诺、分支或返回点；
- 人和 AI 会改变行动的分歧，以及可判别证据；
- `原判断 → 新证据 → 修正结论 → 仍未知` 中最值得恢复的部分；
- 一个不能被高层摘要替代的直接证据切片；
- 已共同确认的后续动作；若只是 AI 建议，明确标为 proposal，不写成共同下一步。

这些只是候选类别，不拥有固定优先级。选择时优先考虑：遗漏该线索是否会导致目的、承重关系、未结事项、分歧或证据基础被错误重建；少量文字能否重新激活较多任务相关结构；最近上下文是否已经足够清楚；是否可以直接引用已有决定、修正结算或证据，而不是重新摘要。若没有实质重建风险，**最小充分重建集可以为空**，不单独显示任何视图。

选择不得依赖对人的永久心理画像或猜测“这个人容易忘什么”。优先使用可观察任务事实、当前责任、已有确认、来源和证据。重建也不是原样恢复旧信念：旧 `next_action`、摘要或状态若已被新事实取代，应先按来源与冲突规则核对并修正，不能因为被保存过就当成当前真相。

呈现层保持轻量、可扫读和跨载体：

1. 一句自然短句已经足够时，不额外造组件。
2. 需要明显视觉锚点时，优先用 Markdown 的 blockquote、粗体和换行形成 1–3 条短线索；标签随语义变化，例如 `Purpose / Checkpoint / Open loop / Divergence / Evidence / Commitment / Proposal / Changed`，不要把这些重新做成必填模板。
3. CLI 或纯文本环境丢失 Markdown 样式后仍应可搜索、可复制、可理解；支持 card、chip、时间线等富 UI 的客户端可以渐进增强，但同一语义不能依赖颜色或图标。
4. 少量、频繁变化的重建线索通常不值得生成图片；只有需要显露真实分支、依赖、空间或多状态关系时，才升级为图或时间线。

例如，在当前最有价值的线索恰好是目的、已发生的模型修正和未结问题时，可以呈现为：

> **Context**  
> **Purpose** — 降低长对话后重建任务模型的成本。  
> **Changed** — 固定 `目标 / 现在 / 下一步` 不再作为语义契约。  
> **Open question** — 如何按重建风险选择线索而不形成新模板？

这里的标签和三条内容都不是固定格式；换一个场景可能只显示一条 `Evidence`，也可能完全不显示。该视图始终是从对话、状态、文档和证据派生的临时人类视图，不独立演化为第二事实源。
