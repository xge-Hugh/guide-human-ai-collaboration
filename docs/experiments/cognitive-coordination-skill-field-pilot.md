# Cognitive Coordination Skill — 日常生态试跑

> 地位：**field pilot / observation surface**，不是正式保障架构、不是随机对照实验，也不自动修改规范。
>
> 当前 pilot carrier：`skills/guide-human-ai-collaboration/SKILL.md`
>
> 云端语义回放：[`cognitive-coordination-cloud-simulation-2026-08-26.md`](cognitive-coordination-cloud-simulation-2026-08-26.md)

## 目的

把更新后的 Skill 部署到真实日常协作中，让长上下文、真实工具、业务语义、疲劳、临时分支、未知线索和真实责任自然产生我们难以预先构造的观察。

本试跑优先回答：

> 新增的认知协调机制是否减少了人为了让协作恢复健康而主动承担的**补偿性元认知劳动**，同时没有把日常工作变成教学、问卷、原始信息倾倒或固定人工参与？

Skill 在这里是**生态观察载体**，不是最终实现形式。有效机制以后可以迁移到常驻 prompt / `AGENTS.md`、Skill、状态、工具脚本、evaluator、Hook 或组合载体。

## 当前 pilot 变化

本轮只重点观察四类新增/强化行为：

1. **责任—能力 viability / 非教学响应**：人仍承担承重责任但判断基础不足或未知时，不因 learning mode 关闭而忽略；也不默认把问题变成课程。
2. **战略性直接证据切片**：AI 做大部分机械工作时，若摘要会遮蔽承重判断需要的关键因果/来源/异常，只暴露一个高价值直接切片。
3. **AI 实质模型修正可观察**：新证据改变 AI 承重判断时，简短结算旧判断如何被替代。
4. **生产性分歧**：共同理解不要求解释模型完全收敛；重要分歧保持可见并寻找判别证据，行动/授权边界仍需必要共识。

旧 Skill 已有的低风险直行、建构保护、风险/证据边界、动态支援等继续生效，不把它们重新包装成新机制。

## 如何形成观察

**不要求人在每个任务填表或主动寻找测试机会。** 日常工作照常进行。

只有出现值得保留的现象时，再留下足够追溯的事实。优先保留：

- 当时真实任务/责任是什么；
- AI 在**第一次合适机会**实际做了什么；
- 人是否需要提醒 AI：看原始证据、继续下潜、纠正模型、保留分歧、不要教学、不要过度暴露细节等；
- 哪个具体代码/日志/请求/来源/反例成为了新线索；
- 行为带来的实际收益或新增摩擦；
- 最终是 `pass / recovered / fail / not_observed`，以及人的补偿劳动。

不需要为了完整而记录所有项；原始对话、代码、diff、日志或 Issue 已经能回答时优先引用它们，不再制造第二份事实源。

## 什么值得回流到项目

### 直接形成 feedback / Issue 的情形

- 新 Skill 在真实承重节点仍需要人反复提醒同一规则；
- 新机制明显 over-trigger，增加无价值问题、教学、raw dump、等待或干扰；
- 战略性证据切片反复产生关键新线索，或反复选择错误切片；
- AI 模型修正虽然被写出来，却没有真正改变后续行为；
- “保留分歧”被滥用成不做决定，或过早共识继续压掉独立判断；
- 发现候选认知模型无法解释的重要协作现象。

### 不自动升级的情形

- 一次感觉良好；
- 一次案例正好符合预期；
- 人看了一个代码片段后说“懂了”；
- AI 没有打扰人；
- 最终任务成功。

这些可以是观察，但不足以证明机制可靠、能力成长或最终 carrier 正确。

## 与 runner / cloud 的回流关系

真实 field observation 先问：**它是否改变真实项目判断？**

- 若现象和根因清楚、风险低，可直接形成小修订或回归 case；
- 若存在 competing explanations，使用 runner 做小规模 `native / carrier A / carrier B` 判别；
- 若是概念/因果未知，先做 cloud 分析、反例或外部研究；
- 若涉及长期重建性/能力轨迹，等待跨时间证据或设计专门纵向观察；
- 不因为 runner 已存在，就把每条规范和每次观察升级成多轮实验。

候选循环：

```text
模型/规范/历史观察
        ↓
低成本 cloud 判别
        ↓
pilot carrier 修订
        ↓
真实日常协作
        ↓
线索 / failure / unexpected success
        ↓
概念诊断
        ↓
按不确定性选择：直接修复 / research / runner / independent review
        ↺
```

该循环本身也是 pilot 方法。如果它在实践中制造重复分析、过高维护成本、假严谨或无法改变决定，应把该方法本身作为对象修订，而不是递归增加更多固定阶段。
