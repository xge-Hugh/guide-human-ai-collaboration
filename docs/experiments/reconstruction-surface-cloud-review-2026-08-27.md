# 重建线索视图：云端语义判别（2026-08-27）

> 地位：**cloud analytical review / candidate mechanism**。本记录不是随机模型效果实验，也不证明长期重建效果。
>
> 目的：在继续修改 Issue #1 的 Skill 实现前，比较固定航标、按重建风险选择线索、以及默认不提供独立视图三种策略，判断“按需选择重建线索”是否产生当前实现没有的实际行为增量，以及它最容易怎样失效。
>
> 依据：[`../spec/workflows.md`](../spec/workflows.md) 的非瀑布工作流语义、[`../../insights/2026-08-25-cognitive-coordination-model.md`](../../insights/2026-08-25-cognitive-coordination-model.md) 的激活 / 修正 / 重建 / 生产性分歧 / 认知分配候选机制，以及 [`../../insights/2026-08-26-decision-driven-evidence-cycle.md`](../../insights/2026-08-26-decision-driven-evidence-cycle.md) 的最低成本判别原则。

## 1. 当前 decision-relevant uncertainty

Issue #1 已经从“箭头链不好读”缩窄为更深的问题：

> 在长上下文、恢复、分叉和模型变化中，AI 应该外化哪些少量信息，才能降低人重建任务相关模型的工作记忆成本，而不制造假的共同状态、固定模板或新的阅读负担？

当前 competing strategies：

- **A — 固定语义航标**：始终围绕 `目标 / 现在 / 下一步`，只让载体和排版适配。
- **B — 自适应重建线索视图**：先判断下一次有意义的判断/行动/审查需要恢复什么，再根据可观察的重建风险选择最小高杠杆线索；允许选择为空。
- **C — 无独立视图 / 只靠自然对话增量**：除非用户明确询问，不额外生成恢复面。

本轮不比较“哪个更漂亮”，而看三者是否减少错误重建、补偿性元认知劳动和无价值提示。

## 2. 从候选认知模型可推导到什么程度

候选模型足以支持**选择目标和候选来源**，但不足以支持固定评分公式、字段数量或阈值。

可推导的选择目标：

> **最小充分重建集**：选择最少的线索，使人能够在当前责任和任务范围内恢复足够的推理路径，继续判断该模型是否适用、仍有哪些未闭合点，以及下一次有意义行动是否成立。

线索候选可由不同机制产生：

- **激活**：目的、旧判断、代表案例、关键历史决定；
- **修正 / 定界**：旧模型、改变它的证据、修正结论、仍未知的边界；
- **生产性分歧**：人和 AI 会改变行动的不同假设、各自后果、可判别证据；
- **证据接触 / 策略性接触**：若摘要会遮蔽承重因果或异常，保留一个高信息直接切片；
- **重建**：能恢复因果关系、适用边界、来源/时间或重新验证条件的提示；
- **认知分配**：比较这些线索的即时/未来重建价值与阅读、打断、重复成本，允许什么都不显示。

重要边界：不得把该过程实现成对人的隐性心理画像或固定认知评分。选择优先使用可观察事实：上下文是否中断/变长、是否有承重模型修正、是否存在明确未结承诺/分支、是否有会改变行动的分歧、是否发生摘要压缩、当前人承担什么判断或验收责任。

## 3. 高信息场景回放

### C1 长上下文后的目的漂移

场景：讨论经历多个技术分支，最近十几轮都在比较实现细节；最初目的“降低人工恢复协作上下文的成本”很久未出现。

**A**：`目标` 有价值；`现在` 和 `下一步` 可能只是重复最近对话。固定三项会携带两项低价值信息。

**B**：重建风险是“局部技术路径替代原始目的”。应优先保留目的，以及一个能解释为何当前讨论仍服务该目的的最近承重结果；若下一步已经明显，不必重复。

**C**：最容易让局部连贯性静默取代原目标，需要人主动追问“我们为什么在做这个”。

**判别**：B 相对 A/C 有净增量；目的不是永久字段，而是在目的漂移风险高时成为高杠杆线索。

### C2 人与 AI 模型未收敛

场景：人认为当前主要风险是误操作；AI 认为是并发重复写入。双方都理解对方，但证据不足。

**A**：单一“现在”容易把其中一方的解释包装成共同状态；单一“下一步”也可能把 AI 的建议包装成共同计划。

**B**：重建风险是“恢复时忘记仍存在承重分歧，或误记为已达成共识”。应显示分歧本身及其可判别证据/行动边界；若 AI 提议动作，明确标为 proposal，而非 shared next step。

**C**：若分歧刚发生且仍在当前上下文，短期可以足够；跨中断/压缩后容易丢失。

**判别**：固定共享状态在该场景有语义风险。B 必须支持 `divergence` 类线索，并区分“已承诺下一步”和“AI 提议”。

### C3 新证据实质改变承重判断

场景：AI 原先认为没有统一 retry infrastructure，后来查到仓库存在并已被当前服务使用。

**A**：`现在` 可以反映新状态，但通常不保存“为什么旧结论被替代”，人未来只记得最后答案。

**B**：重建风险是“信息存在但推理不可重建”。高杠杆线索是旧判断 → 新证据 → 修正结论 → 仍未知边界；这与当前 Skill 已有模型修正结算直接复用，不新造第二套机制。

**C**：如果模型修正已经自然结算，额外卡片可能重复；若发生跨会话恢复，需从已有结算提取最小提示。

**判别**：B 不应重复生成新的事实源，而应重用已经存在的 revision trace；显示与否由恢复风险决定。

### C4 已约定多步计划，中途插入分支

场景：双方已约定“先比较两边全部文件 → 覆盖个人 skills → 核对差异”；比较完成后临时讨论另一问题，恢复时容易忘记剩余两步。

**A**：`下一步` 很有价值，但无法表达“这是先前共同承诺的未完成计划”与“这是 AI 此刻新建议”的区别。

**B**：重建风险是“未结承诺从工作记忆中丢失”。应优先显示已完成 checkpoint + remaining commitment；这里 `next` 有价值，因为它来自既有计划，而不是 AI 单方面设定议程。

**C**：这是 Issue #1 评论已经记录的真实失效类型：公开计划的剩余切片可能被人和 AI 一起忘掉。

**判别**：B 必须支持 commitment/open-loop 线索，并保留其来源地位。

### C5 AI 大量执行后，摘要会遮蔽一个承重异常

场景：AI 完成批量测试和日志分析，绝大多数结果正常，但一次 timeout + retry 暗示第一次可能已经提交；人负责接受错误语义风险。

**A**：目标/现在/下一步都可能不包含真正决定判断的异常证据。

**B**：重建风险是“高层摘要保留任务状态，却失去承载风险判断的原始因果线索”。应选一个 direct evidence slice，并说明其证明边界；这里视觉面可能主要由证据而非状态构成。

**C**：如果完整结果紧邻当前消息且人正在看，独立视图可能不需要；长代理执行或恢复时风险显著增加。

**判别**：B 与现有战略性证据切片机制互补；重建面负责选择/呈现，证据规则负责真实性和证明边界。

### C6 连续、低风险、无分叉的机械执行

场景：AI 连续重命名几个私有局部变量并运行格式检查；目的、动作和后果都在最近上下文中明显。

**A**：固定航标增加无价值阅读和视觉噪声。

**B**：没有 material reconstruction risk；最小充分重建集为空，不显示独立视图，只报告必要结果/变化。

**C**：行为正确。

**判别**：B 必须能退化成 C；“显示一个漂亮卡片”本身不是成功条件。

### C7 恢复后存在过时线索

场景：上次会话记录“下一步：按旧接口实现”，但期间仓库事实变化，新接口已替代旧接口。

**A**：固定 next step 容易把旧导航恢复成当前真相。

**B**：重建不是原样恢复旧信念。应先用可验证事实检查会改变行动的旧线索；过时 cue 应被修正/定界，而不是因为它被持久化就展示。

**C**：完全不恢复也会丢失必要历史，但较少直接执行过时计划。

**判别**：重建面必须继承现有来源权威/冲突规则，不能把“记忆”提升为事实源。

## 4. 判别结果

### 4.1 固定 `目标 / 现在 / 下一步` 不再适合作为语义契约

它在 C1/C4 中包含有价值成分，但在 C2/C3/C5 中会遗漏更高价值关系，在 C6 中制造提示噪声，在 C7 中可能恢复过时行动。问题不是字段本身错误，而是它们不应拥有固定优先级。

### 4.2 “完全不显示”也不足

C 在连续低风险场景很好，但在长上下文目的漂移、计划中断、跨会话模型修正和承重证据压缩中，把恢复劳动重新推给人。Issue #1 原始的工作记忆卸载问题仍成立。

### 4.3 B 产生了可区分的新行为

最小增量可以表达为：

> **在恢复风险有实际价值时，生成一个非权威的重建线索视图；先确定下一次有意义的判断/行动/审查需要恢复什么，再从可验证上下文中选最少的高杠杆线索。线索类型不固定，选择可以为空。**

选择优先考虑：

1. 若遗漏会不会使目的、承重模型变化、未结承诺、重要分歧、证据基础或返回点被错误重建；
2. 该线索是否能以很少文字恢复较多任务相关关系；
3. 最近上下文是否已经足够清楚，重复是否只增加负担；
4. 线索是否来自可追溯事实/已确认内容，还是 AI 推断/提议；
5. 是否有更直接、更低成本的表示，例如引用已有 revision trace / direct evidence，而不是重新摘要。

这是一组后台判断问题，不应显示给人，也不应实现成固定评分或问卷。

## 5. 呈现层候选

大多数目标载体已经支持 Markdown，因此最低实现不应退化为难扫读的代码块或箭头公式。推荐一个稳定但轻量的视觉容器，例如：

```markdown
> **Context**
> **Purpose** — Reduce the cost of reconstructing the task after a long discussion.  
> **Checkpoint** — We rejected the fixed `goal / now / next` semantic schema.  
> **Open question** — Which cues should be selected without creating another template?
```

这里固定的是**视觉语法**，不是字段：

- 只显示 1–3 个当前高价值线索；
- 标签按语义改变，例如 `Purpose / Checkpoint / Divergence / Evidence / Open loop / Commitment / Proposal / Changed`；
- 如果一条自然短句已经足够，使用短句而不造容器；
- CLI/纯文本渲染丢失样式后仍可读；
- 富客户端可以把同一结构升级为 card/chip，但不改变语义或权威；
- 图片、生成式图形不适合只承载少量频繁变化的线索；真实存在分支、依赖、时间关系时才考虑图/时间线。

## 6. 主要反例与失败条件

B 应被视为失败或需要缩窄，如果 field pilot 出现：

- AI 每隔几轮都生成 Context 卡，造成新的视觉/阅读负担；
- AI 根据猜测的“人可能忘了什么”长期跟踪心理状态，而不是基于可观察任务风险；
- adaptive labels 实际稳定退化成新的固定模板；
- AI 用 `Checkpoint` 把自己的总结伪装成双方已确认事实；
- `Proposal` 被恢复成 `Commitment`，或过时 next step 被直接执行；
- 为了提高“重建性”而复制大量正文，形成第二事实源；
- 卡片比一句自然话更长，却没有恢复更多高价值关系；
- 有直接 evidence/revision trace 可引用时仍生成二次摘要，丢失来源与边界。

## 7. 对 Issue #1 / PR #29 的最小建议

本轮 cloud review 足以推翻 PR #29 当前“固定三语义、适配载体”的核心表述，但不支持把更复杂 selector 变成新的固定协议。

建议把 PR 缩窄为：

1. 将“共同航标”改为“重建线索视图 / reconstruction cues”一类非状态机概念；
2. 删除 `一个目标 / 一个当前所处 / 一个唯一下一步` 的固定契约；
3. 增加“最小充分重建集”选择原则与 empty-set 行为；
4. 明确选择根据可观察重建风险，不推断永久心理画像；
5. 用 Markdown blockquote + 强调文字作为常见最小可读载体，但不要求固定标签；
6. 恢复参考继续以 state/document 作为 AI 的索引与控制面，人的重建视图只从权威来源派生，不成为第二事实源；
7. 增加回归场景：生产性分歧、模型修正、未结承诺、直接证据、低风险 no-surface、过时 cue。

## 8. 下一证据层

按候选决策驱动循环，本问题已经通过 cloud analysis 形成了会改变 PR 的判别结果，因此可以进入**可逆 Skill carrier 修订**。修订后不声明机制已验证；在日常真实协作中观察：

- 是否减少人主动回忆目的、提醒未结计划、纠正 AI 假共识、要求恢复关键证据的补偿劳动；
- 是否出现 Context surface over-trigger；
- AI 是否会选择错误 cue、遗漏真正的高杠杆 cue，或把 proposal/推断写成共同事实；
- Markdown 视图是否在实际客户端/CLI 中保持明显更易扫读；
- 若出现 competing explanations，再按需进入 runner / independent review，而不是预先扩大实验。
