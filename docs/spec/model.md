# 协作概念模型

> 地位：**当前语义模型**。本文件定义用于描述人机协作的概念与区分，本身不因为“定义了某个维度”就产生新的规范义务。规范要求见 [`norms.md`](norms.md)。

本模型来自对现有规范、角色/抽象章节、五阶段、认知机制与反模式的逐项审查。目标是减少同一概念被不同历史术语反复重建，而不是建立封闭本体。

## 1. 参与者、角色与权威

**参与者（participant / actor）**表示实际参与协作的人、AI、Agent 或其他行动主体。

**角色（role / function）**表示参与者在某段协作中承担的功能，例如探索、思考、实施、审查、验证、促进或维护。

**权威与责任（authority / responsibility）**表示谁可以决定目的、风险、授权、关键取舍或最终接受，以及谁承担相应后果。

三者必须区分：

> participant ≠ role ≠ authority

同一参与者可以承担多个角色；同一角色也可以由不同参与者承担。承担某个功能角色，不自动取得更高决策权威。人的最终目的、价值与风险裁决边界由规范另行约束。

## 2. 协作状态与发起权

**协作状态（collaboration state）**描述当前会改变双方合理预期、权限、输入需求或保障强度的状态，例如：

- 当前议程与目标；
- 话轮是否已经交接；
- 下一步认知/行动由谁发起；
- 已委托的范围；
- 关键决定由谁承担；
- 当前是否处于探索、深入学习、执行、应急或独立审查等会改变参与方式的模式。

**发起权（initiative）**是协作状态的一部分，不等于最终判断权。AI 能推断一个合理下一步，不等于 AI 已获授权选择共同议程；人允许 AI 临时继续展开，也不自动形成永久委托。

责任相关能力成长本身不必成为独立协作模式。一次短概念连接、对证据的解释或自然任务中的能力观察可以发生在普通交付中；只有当专项练习、较长教学或学习所有权会实质改变双方参与方式、当前行动者或保障要求时，才需要把“深入学习”作为可观察的模式变化处理。

## 3. 抽象层与能力/掌握

**抽象层（abstraction level）**回答：当前在问题的哪一层讨论或行动？

**能力/掌握（capability / mastery）**回答：有什么证据表明某个参与者能在相应情境和抽象层理解、判断、预测、执行、迁移或审查？

两者正交：

> abstraction depth ≠ mastery level

当前旧章节中的 L0–L4 与 M0–M5 是历史上软件研发场景形成的具体表示。后续拆分时，应保留“抽象层与能力证据不同”这一结构性区分，而不预设现有编号是所有领域的通用分类。

**责任相关能力需求（capability demand）**回答：为了实质行使当前仍由某参与者承担的责任，在当前情境和抽象层至少需要什么理解、判断、验证、纠错、识别未知或求助/升级能力？它由责任、后果、可逆性、证据条件和任务语境共同形成，不是对人的永久能力等级要求。

因此应区分：

```text
responsibility
    → contextual capability demand

observed performance + context + abstraction + support
    → capability evidence

capability demand vs capability evidence
    → sufficient / uncertain / meaningful mismatch
```

能力需求高于当前证据能够支持的部分，可以称为**责任—能力失配（responsibility–capability mismatch）**。这只描述当前协作安排中的关系，不等于给人贴“能力不足”的身份标签，也不预设唯一处理方式；规范如何要求协作响应这一失配见 [`norms.md`](norms.md)。

对重复协作，可以观察**能力轨迹（capability trajectory）**：同类责任、情境和支援边界下，可观察能力证据如何随时间变化。轨迹可以表现为增长、稳定、退化或保持未知；它本身不要求能力单调上升，也不能脱离责任、情境和支援条件解释。

## 4. 主张、证据、表示与来源

**主张（claim）**是协作中需要被理解、判断、验证或采用的命题。

**证据（evidence）**是对某个主张提供证明力的可观察依据。证据的意义取决于它覆盖的失效模式、保真度、判别力、独立性与适用范围；一次成功、流畅解释或主观确信都可能是弱证据。

**表示（representation）**是信息被表达、压缩、组织或持久化的形式，例如自然语言、摘要、表格、图、任务状态、审查视图、模板或代码。

**来源与追溯（source / provenance）**说明表示或主张从何而来、经过哪些转换以及什么边界仍然适用。

关键区分：

> derived representation ≠ source

派生表示可以更适合作业，但不能仅因更新、结构化或方便而自动继承来源的完整性与权威。

## 5. 独立性

**独立性（independence）**不是参与者数量、角色名称或会话数量本身，而是相对于目标失效模式，判断信息、假设、推理上下文、输入顺序、验证方法或证据生成路径是否形成了足以降低相关错误的实质分离。

因此：

> reviewer role ≠ independence

独立性可以是审查、验证或评估的保障属性；其证明力不能超过实际被隔离的相关失效来源。

## 6. 风险、可逆性与不确定性

**风险（risk）**描述错误或误解造成的潜在后果。

**可逆性（reversibility）**描述错误发生后恢复或撤销的难度与成本。

**不确定性（uncertainty）**描述当前事实、因果、意图、能力、证据或协作状态仍未被充分建立的程度。

这些维度会影响确认、解释、审查、证据和执行保障的强度，但不等同于任何固定流程级别。

## 7. 当前模型的开放边界

本文件不是封闭词典。只有当新的重要内容回答了现有概念无法无失真表达的不同问题时，才应增加新的语义维度。若现有分类被后续证据或跨领域使用证明不成立，应按项目演进规则缩窄、重分类或取代，而不是为了兼容历史文件继续保留错误区分。
