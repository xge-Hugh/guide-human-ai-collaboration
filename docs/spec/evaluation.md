# 评估模型

> 地位：**当前规格中的评估模型**。本文件说明协作中“评估什么、什么证据能够支持什么结论”。它不要求所有任务采用固定评分、等级或测试流程。

## 1. 分开评估对象

至少区分以下对象：

### 1.1 任务结果

任务结果回答：当前交付、判断或行动是否达到目的，关键不变量是否保持，风险是否被相称验证或接受。

一次任务成功只能直接支持该任务及其证据覆盖范围内的结论，不能自动证明人的独立能力、AI 的普遍能力或某个协作载体可靠。

### 1.2 人的独立能力

人的能力判断回答：在特定领域、情境与抽象层上，人能在多少支援下理解、解释、预测、判断、执行、迁移或审查。

能力不是永久身份标签。Prompt 长短、响应速度、一次错误、一次顺利完成、AI 参与比例或主观自信都不能单独建立能力结论。

对重复协作，还可以单独观察**能力轨迹**：在相近责任、情境、抽象层与支援边界下，可观察能力证据如何随时间变化。轨迹可以表现为增长、稳定、退化或保持未知；一次表现、任务数量、参与时长或 AI 使用频率都不能单独建立“成长”或“停滞”结论。能力轨迹也不要求单调上升，只有与人的持续责任和当前协作目的联系起来才有意义。

### 1.3 人机协作能力

协作能力回答：人和 AI 组合后是否能更可靠地建立理解、判断、行动与反馈，包括是否能暴露风险、纠正误解、保持权威边界、取得适合失效模式的证据并在需要时恢复状态。

对长期或重复协作，还应关注组合是否形成更有效的责任分配与能力结构：AI 是否减少了低价值机械负担，人是否保有足以支撑责任的有效判断基础，以及协作是否系统性维持了本可通过比例性成长机会降低的依赖。这里评价的是组合关系，不等于要求人的全部能力独立于 AI。

持续使用 AI、重复委托或人的独立执行比例没有上升，都不能单独证明协作能力停滞。若责任相关能力基础已经足够、委托边界清楚、人在需要时能够理解后果和纠错，并且这种分工符合共同目的，稳定的高 AI 参与可以是健康协作。

高质量最终结果不等于协作机制本身可靠；如果关键规则只在人反复提醒后才执行，应区分首次表现、经纠偏后的恢复与最终结果。

### 1.4 机制或载体的运行表现

Skill、Agent、状态系统、模板、UI、Hook 或 eval 框架是实现/保障载体。对它们的结构审查、可读性或测试定义，不能代替真实运行表现的证据。

应区分：

> 规范正确性 ≠ 载体结构质量 ≠ 运行表现 ≠ 执行保障 ≠ 最终任务/体验结果

### 1.5 参与者评价按角色、责任和当前目的解释

人和 AI 是性质不同的参与者，不应默认使用一张对称的优缺点清单评价。对人的判断通常关心其在相应支援下是否理解、预测、裁决、执行或迁移，以及这些能力是否足以支撑当前责任；对 AI 的判断通常关心其是否提供充分上下文、保护人的权威与议程、区分事实和未知、校准支援，并在首次合适机会可靠执行关键规则。共同任务结果、协作恢复能力、长期能力结构与人的补偿性劳动仍应另行结算。

这不是为人和 AI 固定永久角色。具体评价维度应随任务责任与当前目标变化；不为形式评价强行安排能力训练、测验或成长结论。即使当前没有明确的深入学习目标，也不能因此忽略“人是否有足以支撑其责任的能力基础”或把重复协作中的可避免能力依赖自动视为无关。

## 2. 能力证据的层次

旧 Chapter 01 使用 M0–M5 描述可观察表现。当前规格保留其核心证据区分，但不把编号当作跨领域永久等级：

| 证据形态 | 可观察表现 |
| --- | --- |
| 接触 | 看过术语、答案或做法，但尚不能稳定说明 |
| 识别 | 能从实例或选项中识别概念、边界或常见模式 |
| 解释 | 能用自己的话说明目的、关系、约束或不变量 |
| 预测 | 条件变化时能预测结果并说明理由 |
| 独立执行 | 在相应支援边界下能完成行动、实现、调试或验证 |
| 迁移与审查 | 能迁移到新场景、发现边界并审查他人方案 |

这些表现不是必须依次通过的考试。不同任务只需要与人的责任以及（若有）更深入学习目标相称的证据；也允许能力状态保持“不确定”。接触或被点明一个成熟概念，可以成为后续学习证据的起点，但不能仅凭“听过术语”声称已经理解或迁移。

## 3. 抽象层与能力证据必须联合解释

能力结论必须带上“在哪个抽象层、什么情境、多少支援”这一上下文，并与人实际承担的责任分开解释。

例如，一个人可以在业务行为与接口边界上形成独立判断，同时把底层实现交给 AI；只有底层细节会改变其取舍、验证或维护责任时，才需要更深层能力证据。反过来，某人不能独立实现底层细节，也不自动证明其无法负责上层判断；关键是其责任相关能力需求是否得到相称支持。

因此：

> capability evidence = observed performance + context + abstraction + support level

而不是一个脱离任务的总分。

责任相关能力需求见 [`model.md`](model.md#3-抽象层与能力掌握)。若要声称能力轨迹发生变化，还需要跨相关任务比较相近责任、情境、抽象层和支援边界下的证据，并显露情境变化、支援变化与证据缺口；不能用一次成功、一次失败或“AI 介入变少”直接证明成长。

## 4. 共同理解也是需要证据的状态

AI 已经输出长篇解释，不等于人已经理解；人说“听起来可以”、沉默或继续对话，也不自动证明共同理解。

当理解会改变关键判断或行动时，可使用与成本相称的 grounding 证据，例如：

- 人用自己的方式重述关键关系；
- 将模型应用到一个具体后果；
- 提出反例或边界；
- 预测条件变化后的结果；
- 通过一个能区分不同理解的实际判断。

不默认要求复述、测验或逐项确认。

## 5. 证据与支援的归因

评估人的能力时，应显露 AI、工具、模板、先例或其他支援在当前表现中的作用。支援不是负面因素，但不能在没有依据时把协作产出全部归因为人的独立能力。

同样，AI 在人纠正后完成任务，也不能把恢复后的最终正确直接算作其首次自主表现。

长期能力结构也需要保留支援变化：若人表现更好只是因为 AI 提供了更多提示，不能直接声称独立能力增长；若人能够在不同情境、较少支援或更高责任下保持判断质量，则可以形成更强但仍有边界的能力证据。

当前项目不设置固定人机贡献比例、总分或排行榜。若未来需要量化，应先说明评价对象、支援边界、证据来源与误差含义。
