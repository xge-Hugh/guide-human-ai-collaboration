# 行动锚定：避免对话代理压缩真实因果链

- **日期**：2026-08-11
- **状态**：`candidate`（与 Issue #2 相邻但不混入其关闭条件）
- **关联**：D-005、D-017、D-061；任务结果 / 个人独立能力 / 人机协作能力三账

## 主张（一句话）

AI 代理可能把“意图—操作—环境反馈—纠偏—结果”压缩成“说话—得到结果”；当目标包含理解、控制或独立能力时，应按需保留一个与真实系统相连的观察、预测、验证或动手锚点。

## 与建构保护的关系

- 建构保护处理认知闭合：AI 不过早替人形成完整问题框架。
- 行动锚定处理实践闭合：AI 不让真实操作和环境反馈完全消失在代理黑盒中。
- 两者都采用微量、渐进、可跳过的支援，但触发条件不同，不合并成单一“铁三角”或每轮仪式。

## 候选形态

根据学习目标、责任、风险、时间压力和人的兴趣，从低到高按需选择：看见真实输出 → 先预测再观察 → 检查 diff / 日志 / 测试 → 执行一个小操作 → 完成局部修改 → 独立处理小闭环。

AI 需要外显的是可验证的行动—证据链：准备做什么、基于什么事实、实际执行了什么、环境返回了什么、证据怎样改变下一步。不要用完整“内心推理”表演替代证据，也不要故意制造失败、固定保留工作比例或用虚假数字承诺能力增长。

阅读和观察也可能形成真实联系，敲键盘不是参与的唯一证明；反过来，只看懂最终结果也不能直接记为独立执行能力。没有迁移或独立操作证据时，应诚实标为待验证。

## 尚未决定

- 它是一般协作底线、学习主模式机制，还是只在特定任务中开启的参与插槽；
- 与代码实施、验证证据和能力快照分别如何分工，避免重复；
- 哪些真实任务信号足以证明行动锚点的收益超过新增摩擦。
